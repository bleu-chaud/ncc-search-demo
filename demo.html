Het probleem: 22 losse scripts

Elke ranking-regel in Elasticsearch is een apart Painless script. Elke script loopt over het document, checkt een conditie en vermenigvuldigt de score. Dit is wat jullie nu beheren:
22 scripts in search-body.json

    


    

        Scroll door de code hierboven. Elke script doet in principe hetzelfde: als product eigenschap X heeft,
        vermenigvuldig de score met factor Y. Maar elk vereist een apart JSON-blok met params, source,
        en de volledige Painless syntax. Wijziging? 22 plekken checken.
    







    
De oplossing: 1 leesbare expressie

    

        Typesense vervangt alle 22 scripts met een enkele sort_by parameter.
        Hier is de volledige ranking — alles in 1 regel:
    


    

        
// Typesense sort_by — the complete ranking
_text_match(buckets:10):desc, boost_score:desc, sale_count:desc
        
    


    

        De boost_score wordt bij het indexeren berekend — een simpele optelsom die alle 22 ES scripts vervangt:
    


    

        
// PHP bij import — vervangt 22 Painless scripts
$boost = 0;
if ($product['recommended']) $boost += 4;   // ES: script factor 4x
if ($product['sale'])        $boost += 2;   // ES: script factor 2x
if ($product['eol'])         $boost -= 5;   // ES: script factor 0.2x
foreach ($product['categories'] as $catId) { // ES: 14 scripts
    $boost += $categoryBoosts[$catId] ?? 0;
}
foreach ($product['properties'] as $propId) { // ES: 5 scripts
    $boost += $propertyBoosts[$propId] ?? 0;
}
        
    


    

        

            
1

            
Tekst relevantie

            

                _text_match(buckets:10):desc
            

            

                Verdeel resultaten in 10 relevantie-groepen. Binnen elke groep
                bepalen de business rules de volgorde. Zo domineert een perfect
                zoekwoord-match altijd, maar bij gelijke relevantie wint
                de aanbevolen camera.
            

        

        

            
2

            
Business rules via boost_score

            

                boost_score:desc
            

            

                Pre-berekend bij indexering. Simpele optelsom: Aanbevolen = +4, Sale = +2, EOL = -5,
                plus categorie- en eigenschap-boosts.
                Een aanbevolen dome camera: 4 + 3 (IP) + 4 (Dome) = +11.
                Aanbevolen dome in de sale: 4 + 2 + 3 + 4 = +13.
                Een EOL product: -5 + 3 (IP) = -2.
            

        

        

            
3

            
Populariteit als tiebreaker

            

                sale_count:desc
            

            

                Bij gelijke tekst-score en gelijke eval-score wint het product
                met meer verkopen. Simpele sortering, geen script nodig.
            

        

    


    
De vertaling: 1 ES script vs 1 TS conditie


    

        

            Elasticsearch — 1 van 22 scripts

{
  "script_score": {
    "script": {
      "params": {
        "factor": 3.5,
        "type": "categories",
        "id": 1710
      },
      "source": "double sum = 1.0;
  for (item in doc['categories']) {
    if (item == 1710) {
      sum = params.factor
    }
  }
  return sum;"
    }
  }
}

            
13 regels JSON + Painless. Herhaal dit 22 keer.

        

        
→

        

            Typesense — 1 conditie

// Bij import:
$boost += $catBoosts[1710] ?? 0;

// In de query:
sort_by: boost_score:desc

            

                De categorie-boost is een simpele array-lookup bij indexering.

                Geen runtime script meer. Sortering op pre-berekend veld.
